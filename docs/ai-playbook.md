# My AI Coding Playbook

## 1. When I reach for AI first
- when I want to start planning a project as mentioned in Module 1
- When I need AI to read a codebase and tell me about something or the project as a whole. Used in Modules 1-3
- when I want to make sure that I covered features end-to-end including testing like in module 5.4

## 2. When I do not reach for AI
- When I need to understand the project that I am working. I used it a lot in modules 1-3
- When it is a deicions that I should make like a review structure, for example the governance worksheet that we wrote in module 5
- When I am not sure about a task, including how it should be like and its constraints. Because I need these information to share them with AI in order for it to give me exactly what I need. I noticed this throughout the whole project.

## 3. My non-negotiables
- When AI does more edits than required/needed, that is why we always add 'Constraints' to the sent AI prompt
- When AI make verdicts that are related to project scope, that is when adding enough details and constraints to make sure that AI doesn't assume things on its own.
- Not giving enough context to AI, as mentioned in the previous points, it is always to give more than less to AI.

## 4. My review rules
- Review AI requested changes almost line by line. I learned and applied this during module 5 because AI was not doing exactly what I asked it to do.
- Have an architectural structure that I AI should follow in order to help me keep track of things. This is exactly what we did in Module 5.
- Edits/changes need to be tested again. Whenever I added a new feature thoughout this whole project, I always ran test cases and added some if missing which made me feel confident about my work.

## 5. What I am still figuring out
- How much should I know about the project before asking AI. It is not easy to know if I am giving enough information to AI.
- When to stop trusting AI. AI seems like a very powerful tool which might give unneeded suggestions that I trust and then I find out that that was a scope creep.
- Focus while using AI and not assuming that AI will not do mistakes or hallucinate. During this whole course I always reviewed what AI gave but in general when I work in a bigger project, it is hard to be certain about what AI is seeing that I might be missing and losing confidence in me which results in me over-trusting AI.
